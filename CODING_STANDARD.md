# Стандарт кодування проєкту ShopOrders

Проєкт: ShopOrders (варіант № 1), C# 12, .NET 8. Автор: Шевченко Р. В., група 472.
Кожен пункт сформульовано так, щоб рецензент міг однозначно сказати «дотримано» або «порушено».

## 1. Загальні положення

1.1. Мова коду — C#, платформа .NET 8; мова ідентифікаторів — англійська, мова коментарів і текстів для користувача — українська.

1.2. Один файл містить один тип верхнього рівня; ім’я файлу збігається з іменем типу (`Order.cs` → `Order`).

1.3. У всіх проєктах рішення увімкнено `Nullable` та `ImplicitUsings` (через `Directory.Build.props`).

1.4. Збірка `dotnet build` у гілці `main` завершується з `0 Warning(s)` і `0 Error(s)`.

## 2. Іменування

| Сутність | Конвенція | Приклад | Антиприклад |
| --- | --- | --- | --- |
| Клас, запис | PascalCase, іменник | OrderLine | orderline |
| Інтерфейс | I + PascalCase | IOrderRepository | Repository |
| Метод | PascalCase, дієслово | CalculateTotal | calc |
| Властивість | PascalCase, іменник | UnitPrice | GetUnitPrice |
| Приватне поле | _ + camelCase | _lines | m_Lines |
| Локальна змінна, параметр | camelCase | totalAmount | ta |
| Константа | PascalCase | MaxLineCount | MAX_LINES |
| Перелічення | PascalCase, однина | OrderStatus | OrderStatuses |

2.1. Скорочення в іменах заборонені (`customerCount`, а не `custCnt`); винятки — загальноприйняті `Id`, `Sku`.

2.2. Логічні властивості й методи починаються з `Is`, `Has` або `Can` (`IsRegular`).

## 3. Форматування

3.1. Відступ — 4 пробіли; табуляція заборонена (у файлах `.csproj`, `.props`, `.json`, `.yml` — 2 пробіли).

3.2. Довжина рядка — не більше ніж 100 символів.

3.3. Фігурні дужки — стиль Allman (відкривна на новому рядку); обов’язкові навіть для однієї інструкції в тілі `if`.

3.4. Між членами класу — рівно один порожній рядок.

3.5. Директиви `using` — на початку файлу, системні перші, невживані видаляються.

3.6. Простір імен — файлового рівня (`namespace X;`).

3.7. Одна інструкція — один рядок; у кінці рядків немає зайвих пробілів; файл — у UTF-8 і закінчується порожнім рядком.

3.8. Порядок членів класу: поля, потім властивості, потім методи.

## 4. Коментарі та документація

4.1. Коментар пояснює «чому», а не «що»; коментар, який переказує код, заборонений.

4.2. Публічні типи й члени бібліотеки `ShopOrders.Core` мають XML-документацію `<summary>` (обов’язково з ЛР № 4).

4.3. Закоментований код у репозиторій не потрапляє.

4.4. Незавершене місце позначають `// TODO(ЛР N): опис`; без номера роботи `TODO` не допускається.

```csharp
// погано: коментар переказує код
// збільшуємо лічильник на одиницю
count = count + 1;

// добре: коментар пояснює причину рішення
// склад округлює вагу вгору, тому й тут Ceiling
weight = Math.Ceiling(rawWeight);
```

## 5. Структура проєкту

5.1. Уся логіка предметної області — у `ShopOrders.Core`; консольний застосунок `ShopOrders.App` містить лише введення й виведення.

5.2. Код `ShopOrders.Core` не викликає `Console.*`.

5.3. Сутності лежать у теці `Domain`; простір імен збігається зі шляхом до теки (`ShopOrders.Core.Domain`).

5.4. `ShopOrders.Core` не посилається на `ShopOrders.App` (залежність лише в один бік).

5.5. Теки `bin` та `obj` не потрапляють до репозиторію (`.gitignore`).

## 6. Правила комітів

6.1. Повідомлення — за Conventional Commits: `тип: суть`, де тип — `feat`, `fix`, `docs`, `chore` або `style`.

6.2. Суть — коротка, українською, до 72 символів, без крапки в кінці.

6.3. Один коміт — одна завершена зміна; після коміту проєкт збирається.

6.4. Завершення лабораторної роботи позначається міткою `labN` (наприклад, `lab1`).
